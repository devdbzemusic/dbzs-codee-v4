# DBZS AGENTS

## Purpose

DBZS is an AI-native modular operating environment focused on:

- local AI orchestration
- runtime management
- modular desktop systems
- reusable architectures
- intelligent agents
- provider abstraction
- scalable AI workflows
- offline-first execution

Agents inside DBZS must always prioritize:

- modularity
- scalability
- maintainability
- runtime stability
- clean architecture
- extensibility
- reusable systems

---

## Core Agent Rules

## Architecture First

Always think like a senior systems architect.

Before generating code:

1. analyze architecture
2. identify reusable systems
3. separate responsibilities
4. avoid monolithic structures
5. design for long-term scalability

Never mix:

- UI logic
- runtime logic
- database logic
- provider logic
- agent logic

---

## Module Philosophy

DBZS uses a reusable module ecosystem called:

DBZS Module Vault (D-M-V)

Rules:

- prefer reusable modules
- avoid duplicated systems
- use composition over inheritance
- keep modules isolated
- modules should remain project-neutral whenever possible

Every module should support:

- metadata
- versioning
- registry integration
- dependency declarations
- isolated testing

---

## Runtime Rules

Runtime systems must be:

- fault tolerant
- restartable
- observable
- isolated
- provider independent

AI runtimes must support:

- local execution
- diagnostics
- provider abstraction
- verification pipelines
- runtime monitoring

llama-server integration is mandatory and managed internally.

---

## Code Generation Rules

Generated code must be:

- production-ready
- modular
- testable
- typed where possible
- documented
- scalable

Prefer:

- TypeScript for frontend/UI
- Python for AI/runtime/backend

Always generate:

- clean folder structures
- reusable utilities
- interfaces/types
- integration examples

Avoid:

- fake implementations
- placeholder architectures
- pseudo systems
- giant monolithic files

---

## UI/UX Philosophy

DBZS UI must feel:

- futuristic
- responsive
- modular
- intelligent
- minimal
- high-performance

Avoid generic enterprise dashboards.

Prefer:

- workspace systems
- detachable panels
- realtime indicators
- context-aware actions
- node/workspace concepts
- neon/cyber inspired hierarchy

---

## AI Behavior

Agents should:

- explain architectural decisions
- explain tradeoffs
- propose scalable alternatives
- optimize for future extensibility

Always think long-term.

DBZS is an evolving platform designed for:

- future runtimes
- future providers
- future AI systems
- future operating environments
- future agent ecosystems

All systems must be designed accordingly.
